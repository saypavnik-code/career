# Fable Roadmap — план работы по итогам архитектурного ревью

**Источник:** Deep Architectural & GUI Review от Claude Fable (передано Павлом 2026-09-04).
**Статус:** черновик плана, ждёт подтверждения baseline-коммита и приоритетов перед первым патчем.
**Важно:** этот roadmap описывает **что чинить**, а не заменяет протокол доставки (`escada_patch_vN.py`, str_replace с проверкой уникальности, тесты + build перед push). Каждый пункт ниже — кандидат в один или несколько патчей.

Ключевые находки Fable выборочно сверены с реальным кодом в repomix-экспорте (не всё ревью — целиком гипотеза, часть уже подтверждена построчно):
- **P0-2** подтверждён дословно: `ai-contract.mjs`, `retrieveCriteria` — `filter((item) => item.score > 1 || ...)` при `currentBoost = criterion.level === currentLevel ? 2 : 1` действительно пропускает любой критерий текущего уровня без совпадений по тексту.
- **P0-3** подтверждён: `inferLevelSignal` в `career-core.mjs` имеет tie-break в пользу более высокого уровня (`LEVEL_ORDER.indexOf(b) - LEVEL_ORDER.indexOf(a)`); `suggestBehaviorRefs` действительно фолбэчит на `candidates.slice(...)` без учёта score при нулевом overlap.
- **P0-1** подтверждён: `importData` вызывает `migrateState(raw, createDefaultState())` без проверки схемы, confirm или бэкапа.
- **P1-3** подтверждён: `reportText` одновременно — и содержимое черновика, и флаг видимости `ReportDraftModal`; `reports.slice(0, 5)` — единственная точка доступа к истории.

Остальные пункты (P1-2, P1-4…P1-10, P2) приняты на веру как правдоподобные по общей структуре кода, но не построчно верифицированы — верификация входит в работу над соответствующим патчем.

## P0 — Критично (данные и доверие к продукту)

Эти три пункта Fable считает нужным сделать **до** любых новых фич. Согласен: P0-1 и P0-2/P0-3 — про потерю данных и про подрыв единственной причины, зачем продукт существует (разделение факта и догадки).

### Патч A — Guarded import + hydration safety (P0-1)
- `isEscadaState(raw)` в core: обязательный `version`, массивы `ideas/wins/notes/reports`. Неизвестная форма — отказ с уведомлением; legacy-формы допустимы только на пути гидратации, не импорта.
- Бэкап перед любой заменой (`escada:backup:<iso>`, хранить последние 3).
- Corrupt primary key → `escada:corrupt:<iso>` + баннер восстановления с "экспортировать сырые данные"; **не** падать на предыдущий ключ автоматически.
- `importData`: `window.confirm` с счётчиками ("Заменить N идей, M wins, K отчётов?"); сброс всех черновиков/UI-состояния при импорте (пересекается с Патчем E, P1-5).
- `try/catch` вокруг `localStorage.setItem`; `QuotaExceededError` → баннер, не молчаливый краш эффекта.
- **Инвариант/тест:** `migrateState({})`, `migrateState([])`, `migrateState({version: 9})` не должны менять существующее состояние без явного подтверждения; corrupt v5 + valid v4 → грузится v4 с уведомлением, v5 сохранён в `escada:corrupt:*`.

### Патч B — Retrieval admission filter + provenance metadata (P0-2)
- Изменить фильтр в `retrieveCriteria`: `overlap > 0 || competencyIds.includes(criterion.competencyId)`; `currentBoost` — только для сортировки, не для допуска.
- `retrieveCriteria` возвращает `{ criterion, overlap, explicit }`, чтобы потребители различали "совпало с записью" и "добавлено для контекста".
- `buildLocalGuidance`: strengths только при `overlap > 0` (или явно выбранная компетенция); иначе — в "предположения/что проверить", без формулировок "уже подтверждается записью". Пустой `strengths: []` — допустимый результат.
- **Инвариант/тест (golden test):** артефакт без пересечения по компетенциям → `strengths.length === 0` локально, и это соответствует поведению внешнего AI ("если оснований недостаточно — сказать прямо").

### Патч C — Provenance split: inferred vs confirmed (P0-3)
Самый крупный по объёму пункт P0. Fable прав, что это "тот самый рефакторинг, который защищает ключевое обещание продукта" — стоит делать отдельным патчем, возможно в 2 подшага.

- Перестать писать производные значения (`levelSignal`, `competencyIds`-если-не-выбраны-явно, `behaviorRefs`) в основные поля факта. Либо считать на чтение (селекторы), либо — если нужна стабильность — хранить под `inferred: { levelSignal, competencyIds, behaviorRefs, engineVersion }`.
- В редакторе (IdeaWorkspace/WinModal): подсказки-чипы с "принять"; сохраняются только подтверждённые.
- `computeGrowthPath` и AI-payload читают только подтверждённые поля; авто-подсказки — визуально отдельный блок "предположения Эскады".
- Убрать upward tie-break в `inferLevelSignal` (P0-3 evidence) — на равенстве fallback на уровень профиля, а не на более высокий уровень.
- Whitelisted-проекция артефакта для AI: только `title, details, nextStep, impact, evidence, metrics, confirmedBy, notes[].text, evidenceNotes[].text, date, competencyIds(confirmed)`. Никогда не отправлять `levelSignal, levelReason, behaviorRefs, ids, timestamps`.
- **Инвариант/тест:** очистка всех чипов компетенций у пользователя должна оставаться пустой (не должна тихо возвращать подсказки); `computeGrowthPath` на фикстуре с только `inferred`-данными → 0 "уже подтверждается работой".
- **Product decision нужен от Павла** (см. раздел ниже): как именно выглядит UI принятия подсказки — авто-принятие при сохранении вообще убрать, или оставить one-click accept.

## P1 — Важно, до существенного расширения фич

Группирую по смысловым кластерам, а не строго по номерам Fable — некоторые P1 логически идут вместе с P0-патчами выше.

### Патч D — Report reachability + print fix (P1-3)
Согласуется с открытым пунктом из project instructions ("отчёт обрывается на последнем шаге") — but Fable нашёл, что это глубже, чем просто "нет кнопки экспорта": сама история отчётов недоступна за пределами модалки с cap=5.
- Список сохранённых отчётов на странице Reports (все, сортировка, фильтр по типу/периоду) — не только последние 5 внутри модалки.
- Явный булев флаг `reportDraftOpen`, отдельно от `reportText` (устраняет "пустой textarea закрывает модалку").
- `saveReport`: обновление при открытии существующего отчёта (`currentReportId`), новая версия — только по явному действию "сохранить как новую версию". Сейчас — всегда новый id, что дублирует при повторном сохранении.
- Починить печать: `window.open('about:blank')` без `noopener` + `printWindow.opener = null` вместо текущего `noopener` (по спецификации возвращает `null` — печать никогда не работала). Экранировать `profile.name` и все интерполируемые строки в `<title>`/`<h1>`.
- **Инвариант/тест:** повторное сохранение открытого отчёта не создаёт дубликат; печать открывает окно (не `null`); отчёт с спецсимволами в имени профиля не ломает HTML.

### Патч E — Editor identity: id вместо snapshot (P1-5, частично P1-6)
- `openNoteId`, `editingIdeaId`, `editingWinId` (+ `'new'`-сентинел) вместо копий сущностей; сущность выводится через `useMemo` из state.
- Редакторы ключуются по id, чтобы `useState(initial)` сбрасывался при смене сущности.
- `importData` сбрасывает все черновики/выборки перед заменой состояния (связано с Патчем A).
- **Инвариант/тест:** сценарий "редактирую заметку → сохраняю → 'Это идея!'" использует актуальный текст, не устаревший снапшот; импорт при открытом редакторе не подмешивает сущности старого датасета.

### Патч F — Unsaved-work guard + PWA reload (P1-6)
- Единый селектор `hasUnsavedWork` (все редакторы + `quickText` + `openNote` + `newIdeaFromNote` + `profileOpen` + onboarding).
- Escape/backdrop на "грязном" редакторе — подтверждение, а не молчаливая потеря ввода.
- SW-reload: неблокирующий тост "Доступно обновление — перезагрузить" вместо автоматического `window.location.reload()` сразу после закрытия редактора.
- `beforeunload` при "грязном" состоянии.
- "Пересобрать черновик" отчёта — подтверждение перед перезаписью отредактированного текста.
- **Инвариант/тест:** Escape на редакторе с несохранёнными данными не приводит к потере ввода; закрытие "Готово" не триггерит немедленный reload.

### Патч G — AI response validation + payload budget (P1-1, P1-2)
- Клиентский вызов `parseAndValidateAiResponse(data, retrieval, action)` перед использованием ответа AI; при исключении — фолбэк на локальный guidance с явной ошибкой.
- `rewrite`: непустой `title` обязателен; merge только непустых полей при apply (сейчас частичный `{title: "…"}` затирает `impact`/`evidence` пустыми строками).
- `AbortController`-таймаут — сейчас зависший эндпоинт оставляет `aiBusy` навсегда.
- Growth guidance: агрегированные сигналы (счётчики по подтверждённым компетенциям, последние N win title+impact), не сырой дамп всех wins — иначе рост числа wins тихо деградирует growth guidance до локального (лимит сервера ~24000 символов) и как побочный эффект пересекается с P0-3 (whitelisted-проекция).
- **Инвариант/тест:** `rewrite: {title: "x"}` не обнуляет `impact`/`evidence`; `rewrite: {}` → явная ошибка `AI_REWRITE_MISSING`, не краш; артефакт с десятками wins не превышает бюджет символов на growth guidance.

### Патч H — Migration normalization + error boundary (P1-4)
- `normalizeReport`, `normalizeLevel(value, fallback)`, `normalizeIsoDate(value, fallbackIso)` в core; применяются в `migrateState` и во всех энтити-нормалайзерах.
- React error boundary вокруг shell с действиями "Экспортировать данные" и "Сбросить только интерфейс" — сейчас невалидное поле (например, `profile.currentLevel = 'Senior'`, невалидная дата) даёт белый экран без доступа к экспорту.
- Version-keyed migration pipeline (`migrations = { 3: ..., 4: ... }`, читает `raw.version`); shape-sniffing — только для legacy без версии.
- **Инвариант/тест:** фикстуры v1–v5 → `migrateState` даёт консистентный результат; невалидные `level`/`status`/`date` не крашат рендер, а нормализуются с fallback.

### Патч I — Multi-tab safety (P1-7)
- `storage`-listener на `STORAGE_KEY`; `meta.savedAt`/`meta.writeSeq` в корне state.
- Если входящий blob новее — ре-гидратация (когда нет несохранённой работы) или баннер "данные изменены в другой вкладке" с блокировкой записи до перезагрузки.
- **Инвариант/тест:** второй таб с более новым `writeSeq` не даёт первому табу молча перетереть данные.

### Патч J — Contract cleanup: enums, types, unify inference (P1-9)
- `ReportType` как enum вместо локализованной строки-лейбла, которую парсят по подстроке (`label.includes('недел')`).
- `career-types.ts` (сущности + `AiRequest`/`AiResponse`); `career-core.d.mts`/`ai-contract.d.mts` против этих типов; удалить `asState` и все `as unknown as`.
- Одна функция инференса компетенций в core, используемая и UI, и `ai-contract` (сейчас `inferCompetencyIds` и `suggestCompetencyIds` — два разных алгоритма с разными нормалайзерами).
- `levelOrder`/`nextLevel` — из модуля знаний везде, не хардкод в трёх местах.
- **Инвариант/тест:** переименование лейбла отчёта не меняет режим (`weekly`↔`monthly`).

### Патч K — Scoped AI state per view (P1-10)
- `aiState[scope]` вместо глобального `aiError`/`aiBusy`; игнорировать ответы, чей `id` не последний для данного scope.
- **Инвариант/тест:** ошибка ревью отчёта не всплывает в следующем открытом редакторе идеи; конкурентные запросы не гонятся за `finally`.

### Product decision, не патч — Idea → Work step (P1-8)
Требует твоего решения, не чисто техническая правка:
- Либо удалить `workItems` полностью (перенести заголовки в заметки, переписать `evidenceForIdea` вокруг `evidenceNotes`/`nextStep`/`status`);
- либо восстановить лёгкий work-list в UI.
Плюс: добавить действие "Архивировать" или убрать статус `archived` как недостижимый; показывать выигранные (`won`) идеи read-only из карточки win.

## P2 — Улучшения (не блокируют фичи, но накапливаются)

Сгруппированы, чтобы не плодить микро-патчи — можно объединять по 3-5 штук за раз, когда будет "уборочный" патч:

- **Даты/таймзона:** `todayIso()` — UTC, `formatDate` парсит как локальное — сдвиг границ периода для UTC+3 в 00:00–03:00. Единый локальный date-helper.
- **Reporting cycle не катится вперёд** после прохождения `cycleEnd` — период должен продвигаться по ритму, пока `end >= today`.
- **Local rewrite — no-op:** возвращает эхо ввода, кнопка "Применить формулировку" обещает улучшение, но ничего не меняет. Вернуть `rewrite: null` локально или переименовать кнопку.
- **`sources` показывает все retrieved, не только cited** — в "Почему Эскада так решила?" сначала cited (или только cited).
- **Legacy `behaviorRefs` формат** (`competencyId:level:index`) не матчится новыми criterion-id ссылками — миграция один раз.
- **Мёртвый код в core (~30%):** `computeInsights`, `computeProgress`, `buildCoachNotes`, `buildReportMarkdown` (Markdown-генератор параллельно с текстовым — два генератора отчётов), `classify/create/captureToIdea/captureToWinDraft`, `normalizeCapture`, `LEGACY_STORAGE_KEY`. Удалить или вынести в `legacy/`-модуль с комментарием.
- **CSS-накопление:** семь наслоенных версий классов, десятки мёртвых селекторов от удалённых фич (`.miniKanban`, `.workItem`, `.coachPanel`, …), брейкпоинтов — 10 штук. Не срочно, но каждое визуальное изменение требует чтения всего файла.
- **Accessibility:** нет focus trap/restore на модалках; дублирующийся `id="modal-title"` при двух модалках одновременно.
- **`isIdeaReadyForWin`** — O(ideas × wins) на каждый drag; предвычислить `Set(wins.map(sourceIdeaId))`.
- **Period validation:** `periodStart > periodEnd` даёт пустой список без сообщения.
- **Пагинация** — списки без неё, не срочно сейчас, но первое, что сломается на тысячах записей.

## Product decisions — нужен ответ Павла до начала соответствующих патчей

1. **Провенанс подсказок (Патч C, P0-3):** какой UX для "принятия" авто-подсказки компетенции — one-click accept-чип при сохранении, или отдельный шаг подтверждения? Это меняет форму данных (`inferred` namespace vs `confirmed`-флаг на существующих полях).
2. **История отчётов (Патч D, P1-3):** нужна ли явная семантика "новая версия" отчёта в UI, или обновление всегда молча перезаписывает текущий черновик до явного сохранения?
3. **Idea → Work (P1-8):** удалить `workItems` насовсем или восстановить work-list в UI? Сейчас это мёртвая, но всё ещё требуемая guidance'ом функциональность.
4. **Приоритет P0 vs открытый вопрос из project instructions** ("экспорт отчёта наружу"): Патч D частично закрывает этот вопрос глубже, чем просто кнопка "скопировать" — но если `escada-product-roadmap.md`/`handoff.md` в репозитории уже говорят, что v27 добавил "Скопировать"/"Печать / PDF" в `ReportDraftModal` (см. предыдущую сверку baseline) — нужно свериться с реальным `git log`, что из этого уже сделано, прежде чем писать Патч D поверх.

## Предлагаемый порядок выполнения

Первая волна (данные не теряются, продукт не врёт):
1. Патч A (guarded import/hydration) — P0-1
2. Патч B (retrieval filter) — P0-2, дешёвый и точечный
3. Патч C (provenance split) — P0-3, самый крупный, возможно 2 подпатча

Вторая волна (UI-состояние не расходится с данными):
4. Патч E (editor id) + Патч F (unsaved guard) — логически одна пара
5. Патч H (migration normalization + error boundary)
6. Патч D (report reachability) — сверить с уже сделанным по v27 перед стартом

Третья волна (AI-контракт и надёжность):
7. Патч G (AI response validation + payload budget)
8. Патч J (contract cleanup/types)
9. Патч K (scoped AI state)
10. Патч I (multi-tab)

P2 — отдельными уборочными патчами по мере накопления, не блокирует новые фичи.

## Прежде чем писать первый патч

Стандартная сверка по протоколу: `git log --oneline -1 origin/main`, сравнить с ожидаемым baseline, **и** решить, какой из открытых вопросов выше (особенно #4) требует ответа прежде, чем Патч A получит номер и код.
